# AGENTS.md

Guidance for AI coding agents working in this repository. Assumes no prior
knowledge of the project.

## Project Overview

**Uniword** is a Ruby gem (by Ribose Inc., metanorma org) for reading, writing,
and manipulating Microsoft Word documents in DOCX (Word 2007+) and MHTML
(Word 2003+) formats. It aims for 100% OOXML specification coverage (760
elements across 22 namespaces) with round-trip fidelity, and ships a Thor-based
CLI (`exe/uniword`).

- Homepage: https://github.com/metanorma/uniword
- Docs site: https://metanorma.github.io/uniword
- License: BSD-2-Clause; required Ruby >= 3.0.0
- Current version: see `lib/uniword/version.rb`

### Technology stack

- **Ruby** gem, packaged via `uniword.gemspec` (files: `lib/**/*.rb`,
  `lib/**/*.css`, `exe/*`, `data/**`, `config/**`).
- **lutaml-model** (`~> 0.8.0`, `>= 0.8.6`) — all XML mapping; every
  serializable model inherits `Lutaml::Model::Serializable`.
- **nokogiri** — XML adapter (configured in `lib/uniword.rb`).
- **rubyzip** — DOCX package (ZIP) handling.
- **omml** — math (OMML) models; Uniword registers an `:uniword` context and
  sets `Lutaml::Model::Config.default_register = :uniword` in `lib/uniword.rb`.
- **thor** — CLI. **rainbow** — CLI colors.
- Dev-only: rspec, rubocop (+ `-rspec`, `-performance`, `-rake` plugins), yard,
  canon (semantic XML comparison, used in specs), benchmark/ruby-prof tooling.

### Key configuration files

- `uniword.gemspec` — gem metadata and runtime dependencies.
- `Gemfile` — `gemspec` plus development tools only.
- `Rakefile` — `rake spec` (default), `rake console`, `rake rubocop`, YARD task.
- `.rspec` — requires `spec_helper`, doc format, excludes `:iso_loading` tag.
- `.rubocop.yml` / `.rubocop_todo.yml` — inherits riboseinc/oss-guides config
  remotely (managed by Cimas; do not hand-edit the inherited parts);
  `TargetRubyVersion: 3.0`.
- `config/*.yml` — runtime rule/profile data shipped with the gem (validation
  rules, style mappings, locale profiles, etc.).
- `data/` — bundled themes (29), stylesets (12), color schemes (23), font
  schemes (25), schemas, resources; shipped with the gem.
- `docs/_config.yml` — Jekyll (Just the Docs + AsciiDoc) documentation site.
- `.github/workflows/` — `rake.yml` (CI), `release.yml`, `docs.yml`,
  `links.yml`; all auto-generated by Cimas and use shared `metanorma/ci`
  workflows. Do not edit by hand.

## Build and Test Commands

```bash
bundle install                       # setup
bundle exec rspec spec/uniword/docx/ # run one spec directory (see warning below)
bundle exec rspec spec/uniword/wordprocessingml/document_spec.rb      # one file
bundle exec rspec spec/uniword/wordprocessingml/document_spec.rb:42   # one example
bundle exec rubocop                  # lint
bundle exec rubocop -A --auto-gen-config   # lint with auto-fix (also `rake rubocop`)
bundle exec rake console             # IRB with uniword loaded
bundle exec yard doc                 # API docs into docs/api
bundle exec exe/uniword help         # CLI smoke test
```

**Do NOT run the full suite with bare `bundle exec rspec`.** lutaml-model
currently leaks `Lutaml::Model::Serializable` instances (~1200 retained objects
per MB of DOCX), so a full run (6000+ examples) grows past 8 GB RSS and
segfaults. `spec/spec_helper.rb` has an `after(:each)` hook that clears
`element_order` references to mitigate, but run individual directories/files
instead. Known timings (see CLAUDE.md): `spec/uniword/ooxml/` ~7s,
`wordprocessingml/` ~20s, `builder/` ~76s, `drawingml/` ~750s,
`spec/integration/` ~12min.

## Runtime Architecture

Model-driven, 4 layers:

1. **Document Model Layer** — Ruby classes for every OOXML element, grouped by
   XML namespace: `Wordprocessingml` (w:, the bulk: paragraphs, runs, tables,
   styles), `Drawingml` (a:), `Math` (m:, via omml), `Vml` (v:),
   `Wordprocessingml2010/2013/2016`, `Office`, `Presentationml`,
   `Spreadsheetml`, etc. Each is a module under `lib/uniword/<namespace>/`.
2. **Properties Layer** — `lib/uniword/properties/` wrapper classes for common
   formatting (internal use only; not exposed in the public API).
3. **Serialization Layer** — XML/JSON/YAML via lutaml-model DSL (`xml do ...
   map_attribute/map_element` blocks).
4. **Format Handler Layer** — `lib/uniword/docx/` (package read/write via
   rubyzip, reconciler) and `lib/uniword/mhtml/`.

Other major modules under `lib/uniword/`:

- `builder/` — fluent Builder API (`DocumentBuilder`, `ParagraphBuilder`, ...)
  for constructing documents; the only place convenience/type-coercing APIs
  belong.
- `cli/` — Thor commands (convert, info, validate, verify, diff, theme,
  template, review, toc, images, spellcheck, headers, watermark, protect...).
- `ooxml/` — package parts, relationships, content types, namespaces,
  schema library.
- `validation/`, `validators/`, `quality/`, `warnings/` — 3-layer verification
  (OPC + XSD + semantic rules).
- `diff/` — document-level and package-level comparison (with Canon).
- `themes/`, `stylesets/`, `template/`, `toc/`, `images/`, `review/`,
  `accessibility/`, `assembly/`, `batch/`, `transformation/`, `generation/`,
  `headers_footers/`, `watermark/`, `protect/`, `spellcheck/`.
- Entry points: `Uniword.new`, `Uniword.load/read/parse`,
  `Uniword::DocumentFactory.from_file`, `Uniword::Builder`.

`lib/uniword.rb` is almost entirely `autoload` (~95% autoload / 5%
`require_relative`). Use `require_relative` only for load-time side effects,
module-level constant references, or eager cross-dependencies — and document
why. Tests mirror `lib/` under `spec/`.

`spec/fixtures/uniword-private` is a private git submodule (SSH URL); specs
depending on it may be unavailable without access.

## Code Style Guidelines

- 2-space indentation, no tabs; max line length 80; `frozen_string_literal`
  magic comment on lib files.
- RuboCop enforced; run before committing. Config is Cimas-managed (remote
  inherit) — keep local overrides minimal.
- No `Struct`/`OpenStruct` — always proper model classes.
- Keep files < 700 lines, methods < 50 lines (CONTRIBUTING.md); follow SOLID
  and MECE.
- YARD docs (`@param`, `@return`, `@raise`, `@example`) on public classes and
  methods.
- Semantic commit messages: `feat(scope): ...`, `fix(scope): ...`, etc.

### Critical pattern: attribute declaration order (Pattern 0)

In every lutaml-model class, declare `attribute`s **before** the `xml do`
block. Declaring them after is silently ignored and produces empty XML output:

```ruby
# CORRECT
class Bold < Lutaml::Model::Serializable
  attribute :value, :boolean, default: -> { true }

  xml do
    element 'b'
    namespace Uniword::Ooxml::Namespaces::WordProcessingML
    map_attribute 'val', to: :value, render_nil: false, render_default: false
  end
end
```

### Model classes vs. builders

- Model classes map OOXML structure 1:1. **No custom getters/setters** in them;
  use lutaml-model `attribute` declarations with proper types. For init-time
  coercion, call `convert_primitive_attributes!` in `initialize` after `super`.
- All user-friendly/convenience APIs (string-instead-of-object arguments,
  coercion, fluent setters) live in `lib/uniword/builder/` classes.
- The public API must not expose wrapper objects (`StyleReference`,
  `ColorValue`, `Properties::*`, etc.) — plain Ruby types only.

## Testing Instructions

- RSpec; **no mocks or stubs**; use `let` for shared variables; one behavior
  per example; MECE coverage (happy path, edge cases, errors, round-trips).
- Every class/module gets its own spec file mirroring `lib/` (e.g.
  `lib/uniword/wordprocessingml/paragraph.rb` →
  `spec/uniword/wordprocessingml/paragraph_spec.rb`).
- Fixtures in `spec/fixtures/` (constant `FIXTURES_DIR`). Generated DOCX
  artifacts go to `test_output/` (auto-created) or `tmp/` — both git-ignored.
- Canon rspec matchers are configured in `spec/spec_helper.rb`
  (`:spec_friendly` profile; `:namespace_declarations` treated as
  non-normative) — use them for semantic XML comparisons.
- `:iso_loading`-tagged specs are excluded by default (`.rspec`); run
  explicitly with `--tag iso_loading` if needed.
- Specs tagged `:skip_if_no_libreoffice` auto-skip unless `soffice` is
  installed; CI installs LibreOffice on Ubuntu/macOS.
- Use the `safe_delete`/`safe_rm_f` helpers from `spec_helper.rb` instead of
  bare `File.delete` for temp-file cleanup (Windows file locking).
- `--profile 30` for slow-example profiling; suite runs in random order with
  `spec/examples.txt` persistence.

## Deployment / Release

- CI: `.github/workflows/rake.yml` (push/PR) via shared `metanorma/ci`
  `generic-rake.yml`, installing LibreOffice first.
- Release: `.github/workflows/release.yml` — manual `workflow_dispatch` (or
  `repository_dispatch: do-release`) to the shared
  `metanorma/ci/rubygems-release.yml`; tags, builds, and pushes to RubyGems.
  The gemspec sets `rubygems_mfa_required`.
- Docs: Jekyll site in `docs/` (AsciiDoc pages in `docs/_*` collections),
  published by `docs.yml` to https://metanorma.github.io/uniword.
- `CHANGELOG.md` is maintained manually — add an entry under "Unreleased" for
  user-facing changes.

## Security Considerations

- RubyGems publishing is MFA-enforced (`rubygems_mfa_required` in gemspec).
- The gem parses ZIP (DOCX) and XML from arbitrary files — be careful not to
  introduce Zip Slip or XXE-style handling when touching `docx/package.rb` or
  Nokogiri parsing paths.
- `spec/fixtures/uniword-private` is a private submodule over SSH; do not
  commit private fixture content into the public repo.
- Do not commit generated artifacts from `test_output/`, `tmp/`,
  `verify_stats/`, or `pkg/`.
